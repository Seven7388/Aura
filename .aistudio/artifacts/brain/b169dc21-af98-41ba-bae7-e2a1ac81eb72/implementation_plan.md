# Aura: SlipNet Native Base64 Link Encoding & Soar Ed25519 Cryptographic Alignment

Comprehensive implementation plan to resolve the two SlipNet client integration issues: eliminating the *"Failed to decode, skipping"* import error by generating native `v22`/`v29` base64 pipe-delimited `slipnet://` URIs, and fixing the Soar public key error by generating valid 32-byte Ed25519 keypairs displayed in both Base64 (44-character) and Hexadecimal (64-character) formats.

---

### User Review & Critical Decisions

> [!IMPORTANT]
> The following decisions were confirmed through interactive clarification and will guide this implementation:

- **Confirmed Decision 1 (Native Base64 Link Encoding)**: All `slipnet://` links generated by Aura (in `aura-installer.sh`, the `aura` CLI, `/etc/aura/client_links.txt`, and the web application) will strictly implement the native SlipNet Android v22/v29 pipe-delimited format encoded in standard Base64. This completely replaces raw query strings (`?domain=...`) and enables instant 1-tap clipboard import without decoder errors.
- **Confirmed Decision 2 (Dual-Format Soar Ed25519 Key)**: Soar keys will be generated as standard 32-byte Ed25519 cryptographic keypairs and displayed in both formats:
  - **Base64** (44 characters, e.g., `tCd7Qm7FolQBkQfQUWLVrLBktDMirri+SlUaAHT1gxM=`)
  - **Hexadecimal** (64 characters)
- **Confirmed Decision 3 (Subdomain Zone Mapping)**: Clarify and enforce the domain zone delegation across all documentation and default configs:
  - `t.<domain>`: DNSTT
  - `n.<domain>`: NoizDNS
  - `s.<domain>`: Slipstream
  - `v.<domain>`: VayDNS
  - `r.<domain>`: Soar Direct (public destinations)
  - `rs.<domain>`: Soar SSH (proxied to OpenSSH `:22`)

### 3. Key Technical Decisions & SlipNet Specification

#### Decision 1: Native Pipe-Delimited Field Structure
SlipNet's internal parser parses pipe-delimited (`|`) strings encoded with `base64.StdEncoding`:
- **v22 (Standard DNS / TLS Tunnels - 60 Fields)**: Used for DNSTT (`dnstt`), NoizDNS (`sayedns`), Slipstream (`ss` or `slipstream_ssh`), VayDNS (`vaydns`), StunTLS (`ssh`).
  - Field 0: Version (`"22"`)
  - Field 1: Tunnel Type (`"dnstt"`, `"sayedns"`, `"ss"`, `"vaydns"`, etc.)
  - Field 2: Profile Name (e.g. `"dnstt-aura"`)
  - Field 3: Tunnel Zone Domain (e.g. `"t.yourdomain.com"`)
  - Field 4: Resolvers (e.g. `"8.8.8.8:53:0,1.1.1.1:53:0"`)
  - Field 11: Public Key (hex Curve25519 or base64)
- **v29 (Soar Multipath DNS Tunnels - 82 Fields)**: Used for Soar Direct (`soar`) and Soar SSH (`soar_ssh`).
  - Field 0: Version (`"29"`)
  - Field 1: Tunnel Type (`"soar"` or `"soar_ssh"`)
  - Field 11: 32-byte Ed25519 Public Key (Base64)
  - Field 79: Soar Discovery (`"0"`)
  - Field 81: Soar TCP Mode (`"auto"`)

#### Decision 2: 32-Byte Ed25519 Key Generation
In `aura-installer.sh` and `aura`, generate the Ed25519 keypair using OpenSSL 3 / Python 3:
- Generate 32-byte seed: `openssl genpkey -algorithm ed25519`
- Extract raw 32-byte public key:
  - 44-character Base64 format: `openssl pkey -in soar.key -pubout -outform DER | tail -c 32 | base64`
  - 64-character Hexadecimal format: `openssl pkey -in soar.key -pubout -outform DER | tail -c 32 | xxd -p -c 32`
- Both formats will be stored in `/etc/aura/keys/soar.pub` and `/etc/aura/keys/soar.hex` and printed for the user.
